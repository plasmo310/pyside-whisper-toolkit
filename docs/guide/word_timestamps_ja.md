# 日本語で単語タイムスタンプを扱うときの注意

- Whisper の単語タイムスタンプは cross-attention の重みを **DTW（動的時間伸縮）**
  で整列して推定した「推定値」です。強制アライメント専用ツールほどの精度はなく、
  ±100ms 程度のずれは普通に起きます。
- 日本語は分かち書きしないため、「単語」は Whisper のトークン単位（＝形態素とは
  一致しない）で区切られます。形態素単位で扱いたい場合は、得られた文字列を
  MeCab / SudachiPy の解析結果に対応付けてください。
- `probability` はその語の確信度です。低い箇所は聞き取り誤りの候補なので
  `--min-prob` でレビュー対象を絞れます。

**正解のテキストが手元にある場合**（歌詞・台本・原稿）は、③
[sync_lyrics](../cli/sync_lyrics.md) で時刻を保ったまま文字だけを貼り直せます。
合わせて、そもそもの誤認識を減らす手もあります。

- `--initial-prompt` に固有名詞や特徴的なフレーズを渡すと表記が揃いやすくなります。
  ```bat
  python -m wsptoolkit.cli.word_timestamps input\audio\song.wav -l ja -m large-v3 --initial-prompt "ミーアキャット 見張る 禁物"
  ```
- モデルを `small` → `large-v3` に上げると一致率が目に見えて上がります。
  ③ が出す**一致率**を指標にすると、プロンプトやモデルの効果を数値で比較できます。
- 歌ものは**ボーカル分離した音声**（伴奏を除いたトラック）を入力にすると認識が
  大幅に安定します。

## 長い曲・繰り返しの多い曲で後半が崩れるとき

サビや掛け声（「キョロキョロ…」の連呼など）が続く区間で Whisper のデコーダが同じ
トークンのループに陥り、そこから先の数十秒が

- 1 セグメントに 20〜30 秒の時間幅が付く（その区間の単語 `probability` がほぼ 0）
- 単語の時刻が途中で数十秒ワープする（例: `77.3s` の次の語が `104.1s`）
- **その先の歌詞（1 コーラス分など）がまるごと転写されない**

という壊れ方をすることがあります。③ の一致率が急に落ち、`*`（補間）行が後半に
かたまっているのが目印です。**`-m large-v3` に上げても直りません**（モデルの
精度不足ではなくデコードの暴走が原因）。

主な引き金は **VAD が曲中の長い無音（間奏）を削り、前後の歌をくっつけてしまう**
ことです。間奏を挟んで「キョロキョロ」が地続きになり、デコーダがループに入ります。

**まず VAD を切るだけ**を試してください。これが単独で一番効きます
（GUI なら `VAD Filter` を OFF、CLI なら `--no-vad`）:

```powershell
python -m wsptoolkit.cli.word_timestamps song.wav -l ja -m large-v3 --no-vad
```

`input\audio\キョロキョロ・ミーアキャット_vocal.wav`（137 秒、83〜99 秒が間奏の
無音）での実測:

| 実行 | ③ の一致率 | 補間行 | 3 番の歌詞 |
| --- | --- | --- | --- |
| 既定 (`-m large-v3`) | 0.51 | 6 行（後半に集中） | 全部補間で復活せず |
| **`--no-vad`** | **0.66** | **0 行** | `どんな危険が来たってさ`〜`首がこっちゃった` まで実音声で復活 |
| `--no-vad --no-condition-on-previous-text` | 0.62 | 0 行 | 復活するが `--no-vad` 単独よりわずかに悪い |
| `--no-vad --no-repeat-ngram-size 3` | 0.17 | ほぼ全行 | 曲全体が 99〜111 秒に圧縮＝崩壊 |

`word_timestamps.py` には補助的なフラグもありますが（faster-whisper 1.2 以降）、
**この曲ではどれも `--no-vad` 単独に及びませんでした**。効かないときの次の一手として:

| フラグ | 既定 | メモ |
| --- | --- | --- |
| `--no-condition-on-previous-text` | 使う | 直前の出力を次区間のプロンプトにしない。ループの後方伝播を止める。他の曲では有効なことも |
| `--no-repeat-ngram-size N` | `0` | 同じ N-gram の連続生成を禁止。**曲頭やサビの連呼まで潰し**、③ の突き合わせが崩れることがある |
| `--hallucination-silence-threshold SEC` | なし | ハルシネーション検出時に無音区間をスキップ。閾値が小さいと冒頭の歌まで消える |

> VAD を切って認識すると曲中の長い無音（間奏）がそのまま残るので、③ は
> `--keep-blank`（GUI なら `Keep Blank`）を付けて実行してください。間奏区間で
> 歌詞が消えるようになります（`--max-gap-fill` が既定で効くので、間奏をまたいで
> 歌詞が引き伸ばされることはありません）。

## 時刻そのものを作り直したい場合

根本的には、正解の歌詞が手元にあるなら**強制アライメント**の方がこの種の破綻に
強いです。既知のテキストを音声に置くだけなので、聞き逃しやループが原理的に起きません。

外部の強制アライメント (wav2vec2) を使う
[WhisperX](https://github.com/m-bain/whisperX) や
[stable-ts](https://github.com/jianfch/stable-ts) が選択肢になります。
ただしどちらも `torch` / `torchaudio` を必要とし、数百 MB〜数 GB の追加ダウン
ロードになります（stable-ts なら
`model.align(audio, text, language="ja", original_split=True)` の一発です）。
本ツールは faster-whisper だけで完結させたいので、③ のテキスト照合方式を採っています。
