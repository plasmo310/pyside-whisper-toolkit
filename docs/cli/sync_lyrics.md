# ③ 歌詞との突き合わせ — `wsptoolkit.cli.sync_lyrics`

② が出す `.words.json` は **Whisper が聞き取った文字**なので、「番さ/晩さ」
「禁物/金持つ」のような誤認識がそのまま時刻に紐づいています。手元に**正解の
テキスト（歌詞・台本・原稿）がある**なら、音声を処理し直さなくても

> 正解テキスト × 認識結果 を `difflib` で照合して、**時刻の上に正しい文字を貼り直す**

だけで済みます。③ はそれをやって、カラオケ字幕の **LRC** を書き出すサンプルです。
**音声もモデルも触らない純粋な後処理**なので実行は一瞬で、テキストを直しながら
何度も回せます。追加インストールは不要（標準ライブラリのみ）。

```bat
REM ② で JSON を作ってから、③ で歌詞を当てる
python -m wsptoolkit.cli.word_timestamps input\audio\song.wav --language ja
python -m wsptoolkit.cli.sync_lyrics song.words.json --lyrics input\lyrics\song.txt

REM 字幕でも確認したいので SRT も出す
python -m wsptoolkit.cli.sync_lyrics song.words.json --lyrics input\lyrics\song.txt -f lrc,json,srt

REM 表示が遅く感じるので全体を 0.3 秒早出しする
python -m wsptoolkit.cli.sync_lyrics song.words.json --lyrics input\lyrics\song.txt --offset -0.3

REM 1文字ずつ光らせる拡張 LRC にする
python -m wsptoolkit.cli.sync_lyrics song.words.json --lyrics input\lyrics\song.txt --word-tags
```

## 歌詞ファイルの書き方

**UTF-8 で 1 行 1 フレーズ**。空行・`#` で始まる行・`【1番】` のように行全体が
括弧で囲まれた見出し行は自動でスキップされます。

```
# コメント行
【1番】
キョロキョロキョロキョロキョロ
キョロキョロ見張るよ 見上げれば
小さな穴から頭ぴょっこり
```

## 実行例

```
[info] 歌詞 29 行を読み込みました (スキップ 7 行)
[info] 認識結果 242 words / duration=137.92
[00:00.69] キョロキョロキョロキョロキョロ
[00:03.25] キョロキョロ見張るよ 見上げれば
...
[02:06.96] 夢を見ていた *

--- 認識 → 歌詞 の差分 ---
[00:06.11] (認識なし)           → れば               ※ 時刻は前後から補間
[00:16.78] 晩                → 番
[00:30.26] 金持つ              → 禁物
[01:08.30] シュート             → 周到

[info] 一致率 88.6% (歌詞 306 文字中 271 文字が一致)
[info] 29/29 行に時刻を付けました (補間 1 行)
[info] wrote output\song.lyrics.lrc
```

**この差分レポートが本体**です。「シュート → 周到」のように、**時刻はそのままで
文字だけが正しく差し替わっている**ことが確認できます。一致率が低い・`*`（補間）が
多いときは、たいてい**歌詞ファイル側**の問題（行の切り方が歌と違う、掛け声や
コーラスが書かれていない、2 番の歌詞が違う）なので、そこを直して再実行してください。

出力ファイル: `output\<名前>.lyrics.lrc` / `.lyrics.json` / `.lyrics.srt`

## オプション

| オプション | 既定値 | 説明 |
| --- | --- | --- |
| `--lyrics` | **必須** | 正解の歌詞テキスト (UTF-8, 1行1フレーズ) |
| `-f, --formats` | `lrc,json` | `lrc` / `json` / `srt`。`none` で書き出さない |
| `--offset` | `0.0` | 全時刻に加算する秒数（負値で早出し） |
| `--max-gap-fill` | `0.6` | 丸ごと聞き逃した区間を歌詞で埋めるときの 1 文字あたり上限秒。長い間奏で歌詞が引き伸ばされるのを防ぐ。`0` で無効 |
| `--word-tags` | — | 拡張 LRC (`<mm:ss.xx>` の文字タグ) を付ける |
| `--title` / `--artist` | なし | LRC の `[ti:]` / `[ar:]` タグ |
| `--report` | — | 一致した箇所も含めて差分を全件表示 |
| `--keep-blank` | — | 歌詞の空行を LRC に空タグ行として残す（間奏で歌詞を消す目印） |
| `--no-end-tag` | — | 最終行の後ろに終了時刻だけの行を入れない |

## 仕組みと限界

- 文字を 1 文字ずつ正規化（NFKC → カタカナをひらがなに → 記号と空白を除去）して
  から `difflib.SequenceMatcher` で照合します。長音符 `ー` と促音 `っ` は発音
  そのものなので落としません。
- 一致した文字は認識結果の時刻をそのまま使い、**誤認識だった区間は時間幅を歌詞の
  文字数で比例配分**、**聞き逃していた区間は前後の時刻から補間**します。補間は
  1 文字 `--max-gap-fill` 秒で頭打ちにするので、長い間奏を挟んで丸ごと聞き逃した
  箇所でも歌詞が間奏いっぱいに伸びません（`--keep-blank` と併用すると間奏中は
  歌詞が消えます）。
- 漢字とかなの揺れ（「見張る」と「みはる」）は形態素解析なしでは吸収できません。
  一致率を見ながら歌詞ファイル側の表記を寄せてください。
- **時刻そのものの精度は ② のまま**です。時刻自体を作り直したい（＝真の強制
  アライメント）場合は [../guide/word_timestamps_ja.md](../guide/word_timestamps_ja.md)
  を参照してください。
